# Guest MIR Adoption Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adopt upstream MIR/baseline while compiling inside the guest, and qualify runner, snapshot and Yurt execution.

**Architecture:** Stack on NightMonkey PR #2 and selectively import pinned upstream compiler/runtime changes. Restore guest FFI and both installation hosts; guest MIR uses sequential prebuilding, host tools retain optional Rayon. Engine hooks land in their owning Firefox fork.

**Tech Stack:** Rust/Cargo, C++/CMake, SpiderMonkey ff147, waffle 0.3.3, WASI and Yurt Wasm targets, Wasmtime.

**Spec:** `docs/superpowers/specs/2026-10-17-guest-mir-design.md`, dual-review approved at `2b458fd30e93371122352f9c91a69b944d0050db`.

## Global Constraints

- Keep compilation in the guest; no `night_compile` or `InprocHostCompile`.
- Stack on fork PR #2 (`yurt-host`, `dda91dc5243720d297abd07caf81d8f756da9ebc`); never edit its branch. Refresh before each integration/push.
- Import upstream compiler head `8f5360d70707679a9080edf6a4dcd4f65d89aa71` only; audit later movement before adoption.
- Engine hooks source: `08702e6f7b6c6d9a2ebf9c0cfc37ccebdd395706`, base `f0c060c52260d41fc631a14cda05372ad1c2cbe1`.
- Preserve snapshot mode, guest FFI/staticlib, runner installation and Yurt assembler.
- Use `--locked` for host Cargo gates. Retain normal `wasm-encoder` dependency; adopt waffle 0.3.3. Do not update unrelated dependencies.
- Guest compiler excludes Rayon; host parallelism is optional. Preserve MIR as the default and baseline as explicit selection.
- Reserve before compilation; blob i installs at base+i. Bound: `11 + 4*scripts + regex_variants`, including one spare/script.
- Keep ABI/layout/opcode checks and GC invariants. No exclusion may hide a regression.
- Commit red behavioral tests before fixes. Mutation proof must fail for the intended defect.
- Build locally first. No AWS provisioning under this plan; report local limitations before changing infrastructure.
- No merge authority. Draft PRs remain drafts until all applicable local gates, required hosted checks and dual review pass.

## Review Focus

1. MIR silently declining to baseline: require a positive `mir` tier witness, not just strict coverage (Tasks 3, 5).
2. GC or invalidation during a MIR exit: preserve values and discard stale property/method assumptions (Tasks 2, 5).
3. Nonzero reserved base and companion bodies: direct calls and adapters must address the installed functions (Tasks 3, 4, 5).
4. Compiler/install failure: never arm partial scripts or close an already consumed/reused reservation fd (Tasks 4, 5).
5. Malformed snapshot/descriptor and lockfile feature unification: reject invalid input and keep guest Rayon disabled (Tasks 3, 4, 5).

## Execution choice and stop conditions

Recommend native execution in this session because import, FFI, engine and
assembler adaptation share interfaces and state. Independent Claude/Codex
review remains mandatory; execution delegation is the user's choice at Gate 2.

Gate 2 covers this committed plan, including the clarified spare bound, options
ABI and positive tier witnesses. Stop and return to design approval for a new
host compile architecture, expanded native-target implementation or >2x
integration growth. An unavailable engine/SDK/target or failing gate is a
qualification blocker; it is never permission to declare the PR mergeable.
